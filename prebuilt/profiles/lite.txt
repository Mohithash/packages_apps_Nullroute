# Nullroute profile — LITE
# DESC: Light filtering. The fewest false positives of the three: blocks the ad and tracker endpoints almost nobody misses, and leaves the ambiguous tail alone.
#
# Measured 2026-08-23 (SPEC §7.6): 42,832 domains after suffix collapse,
# ~1.2 MB resident in netd (103 KB filter + 1.0 MB table at 2^17 + allow + redirect).
#
# Line format — see prebuilt/README.md:
#   <url> # <Name>              block source
#   @<url> # <Name>             allowlist seed (parsed as ALLOW regardless of the
#                               list's own syntax)
#   # OFF # <url> # <Name>      shipped but disabled by default
# The user's overlay lives in profiles/lite_added.txt and profiles/lite_removed.txt;
# this file is never rewritten by the app.
#
# NOTHING BELOW IS BAKED INTO THE IMAGE. Every URL here is fetched and compiled
# on-device on first sync. HaGeZi and r-a-y are GPL-3.0, and a merged blob
# derived from them inside a verity-protected signed image is exactly the
# anti-tivoization hazard SPEC §7.6/§10.5 calls out. Compiling on-device means
# the derivative work is created by the user, on the user's device. Do not
# "optimise" this by shipping a precompiled index — see prebuilt/README.md.

# Allowlist seeds — applied on every build, in every profile.
#
# These two, and only these two, are also SourceCatalog.alwaysAllowSources in
# the app. The two lists must stay identical: the catalogue is what the fetch
# path actually applies, and this file is what an OTA can change without an APK.
#
# ⚠️ hagezi's blocklist-referral and whitelist-referral are the SAME 1,604
# domains with opposite intent. Ship exactly one. We ship the whitelist:
# affiliate and referral link redirectors are load-bearing for shopping,
# cashback and invite flows, and blocking them produces "the link does nothing"
# reports that are impossible for a user to trace.
@https://raw.githubusercontent.com/hagezi/dns-blocklists/main/wildcard/whitelist-referral-onlydomains.txt # HaGeZi referral allowlist
@https://raw.githubusercontent.com/hagezi/dns-blocklists/main/share/ultimate-known-issues.txt # HaGeZi known-issues allowlist

# NOT allow seeds, and the reasons are measured, not assumed. A file living
# under hagezi's share/ directory is not automatically an allowlist — the two
# above are described as such in the upstream README, and these three are not:
#
#   share/ad-shield-subdomains.txt   1,814 entries, 1,552 of them (86%) are
#     BLOCKED by HaGeZi Pro++. It is a blocklist fragment: the randomised
#     subdomains AdShield rotates through to defeat filtering. Applying it as an
#     allow would strip ~1,500 live ad hosts back out of every profile — the
#     same inversion the referral warning above is about, with no symptom the
#     user could ever notice.
#   share/apple-private-relay.txt    22 Private Relay endpoints, 5 of which the
#     doh-vpn-proxy-bypass add-on exists to block. Allowing them would silently
#     nullify part of that add-on, to enable an iOS/macOS feature that does not
#     exist on Android.
#   share/microsoft.txt              A menu, not a recommendation: upstream
#     describes it as "which domains to unblock for which feature". Applying all
#     74 wholesale force-allows Microsoft telemetry (self.events.data.microsoft.com
#     among them) in every profile including AGGRESSIVE, with no toggle. It
#     belongs behind a category switch, next to the OEM-telemetry add-on.

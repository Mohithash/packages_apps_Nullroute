# Nullroute — anti-fraud / device-fingerprinting carve-out.
#
# Overlay stage 7(e) of the compile pipeline (SPEC §6.5): by default every line
# here is applied as an ALLOW, which strips these domains back OUT of whatever
# HaGeZi, StevenBlack or 1Hosts put in. Only if the user opts the "Anti-fraud
# fingerprinting" category IN does the overlay flip and the entries block.
#
# WHY THIS EXISTS. What actually breaks banking, brokerage and card-issuer apps
# is not ad domains — it is the risk engine. These SDKs run before the login
# screen appears, and their failure mode is not "an ad is missing", it is
# "login failed, try again later", "device not recognised", an infinite loading
# spinner, or an account lock after three retries. The user does not attribute
# any of that to an ad blocker, so it arrives as "the ROM broke my bank".
# See SPEC §10.3.
#
# These are genuinely privacy-hostile — full device fingerprinting, sensor and
# behavioural telemetry — which is exactly why the category exists at all. It is
# opt-in rather than absent: the user gets to make that trade, informed, with a
# named FP-risk chip on the toggle.
#
# Syntax is a bare domain, i.e. K_SUFFIX: apex AND all subdomains. The risk
# tables in §10.3 write these as `*.threatmetrix.com`; the apex is deliberately
# folded in here because an allow overlay that misses the apex leaves a hole
# that presents as an intermittent login failure.
